# 🎱 Shot Caller **I’ll Call the Shots.** Shot Caller is a mobile-first pool shot-planning tool built to answer a simple question: **Given the current table layout, what shot should I actually play?** Rather than functioning as a basic angle calculator, Shot Caller evaluates the physical relationship between the cue ball, object ball, pockets, cushions, and available table space to recommend a playable shot. The goal is to turn a table layout into a clear visual plan that a player can understand and execute. ## What Shot Caller Does Shot Caller allows a player to: - Position the cue ball and object ball directly on a true **2:1 pool-table layout** - Select a specific target pocket or allow the app to choose one - Choose between **Auto, Cut, and Bank** shot types - Calculate direct cut shots using **ghost-ball collision geometry** - Calculate one-rail banks using **reflected-pocket geometry** - Display the recommended cue-ball path directly on the table - Display the object-ball route to the selected pocket - Show the exact cushion contact point for bank shots - Show where the cue should contact the cue ball - Show the corresponding contact point on the object ball - Add an **8-ball obstruction** when another ball is blocking the natural route - Move the 8-ball anywhere on the table - Recalculate the available shot when the obstruction changes - Prevent balls from being placed on top of one another - Keep the visual table and mathematical shot model synchronized through a shared physical coordinate system ## Built for Real Table Problems A useful pool shot planner cannot assume that every shot is simply: **Cue Ball → Object Ball → Pocket** In a real game, another ball can block the cue-ball path, interfere with a cut, eliminate a bank, or force the player to find a completely different route. Shot Caller therefore allows an 8-ball to be added as a real physical obstruction. The solver checks that obstruction against the relevant portions of the shot path instead of simply drawing a route through it. This creates the foundation for a more advanced table model in which multiple balls can eventually be represented and considered simultaneously. ## Shot Types ### Auto Auto evaluates the available cut and one-rail bank routes and selects the strongest available candidate based on the current geometry. ### Cut Cut forces the solver to look for a direct object-ball route using ghost-ball collision geometry. ### Bank Bank forces the solver to evaluate one-rail bank routes using cushion reflection geometry. The objective is not to recommend a bank simply because one is mathematically possible. Bank and cut candidates are compared using route length, cut severity, and physical feasibility. ## Physical Model Shot Caller uses a normalized physical coordinate system: - Table dimensions: **100 × 50 units** - Standard pool-ball diameter: **2.25 inches** - Ball radius: **1.125 inches** - Cushion centerlines account for the physical radius of the ball - The same coordinate system controls both the table graphics and the shot calculations ### Cut Geometry Direct shots use ghost-ball geometry. The intended object-ball travel direction determines where the cue ball must be positioned at impact. The solver then checks whether the cue ball can reach that ghost-ball position and whether the object ball has a clear route to the pocket. ### Bank Geometry One-rail banks use a reflection method. The intended pocket target is reflected across the selected cushion. The object-ball path to that reflected target determines the physical cushion contact point. The actual bank route displayed on the table is the same route used by the solver. ## Obstruction Detection When the optional 8-ball is present, Shot Caller treats it as a real ball-sized obstruction. The solver checks whether the 8-ball interferes with: 1. Cue ball → ghost-ball path 2. Object ball → pocket path 3. Object ball → bank contact 4. Bank contact → pocket If an obstruction makes a route invalid, that route is rejected rather than being presented as a viable shot. ## Mobile-First Design Shot Caller was designed around the table being fully usable on a phone or tablet. The table maintains a true **2:1 aspect ratio**, with the playing surface, pockets, balls, route markings, and interaction coordinates scaling together. Touch targets are intentionally larger than the rendered balls so the player can reliably select and reposition balls without needing to tap the exact visual center. ## Visual Shot Guidance Shot Caller is designed to make the recommendation understandable without requiring the player to interpret raw geometry. The table displays: - Cue-ball aiming route - Ghost-ball position - Object-ball route - Bank route - Cushion contact point - Suggested pocket - Selected balls - 8-ball obstruction The side panel also summarizes the recommendation in plain language. ## Limitations Shot Caller is a geometry-based shot planner, not a complete pool-physics simulator. Real-world results can vary based on: - Stroke speed - English / spin - Throw - Cloth condition - Cushion response - Pocket shelf depth - Pocket geometry - Ball condition - Table condition - Elevation - Environmental factors The current system is intended to answer: **“What is the strongest geometric shot to consider?”** It is not intended to guarantee that a particular stroke will fall. ## Future Development The long-term goal is to evolve Shot Caller from a basic shot calculator into a practical visual pool assistant. Potential future capabilities include: - More accurate pocket-mouth acceptance - Improved bank-shot selection - Better cut-angle difficulty modeling - Multiple object balls - Full multi-ball obstruction mapping - Position-play recommendations - Cue-ball landing zones - Speed recommendations - Spin / English considerations - Safety-shot recommendations - Multi-rail banks - More natural pool-player instructions - More sophisticated shot-quality scoring The core principle should remain: > **The shot shown to the player should be the shot the calculation actually evaluated.** Shot Caller should prioritize **physically valid, understandable, playable pool shots** over technically possible but impractical mathematical solutions.
